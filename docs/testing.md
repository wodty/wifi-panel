# wifi-panel 测试手册

四层测试，从秒级自动检查到真机验收。建议按顺序做，问题会定位得很快。

---

## 第 0 层：环境自检（30 秒）

```bash
# 中枢是否在跑
curl "http://127.0.0.1:8765/api/ping?token=panel123"
# 期望：{"ok":true,"agent_online":false}

# adb 是否可用（电视控制需要；Docker 镜像已内置）
adb version

# PC 端依赖
python -c "import pynput, websockets; print('deps ok')"
```

---

## 第 1 层：自动化测试（各 1-2 秒，不需真机）

```bash
# 先确保中枢运行
python -m uvicorn server.main:app --host 0.0.0.0 --port 8765

# 另开终端：
python tests/test_relay.py             # 10 项：鉴权/转发/断线双重兜底/布局 CRUD
python tests/test_tv.py                # 13 项：三协议配置、非法输入、离线优雅降级
python tests/test_release_per_remote.py # 5 项：多设备场景下单台断线只释放它自己的键
python tests/test_templates.py         # 6 项：模板清单、默认播种、实例化、非法模板
```

> 两个脚本请**分开执行**。链式 `&&` 在部分终端上会被外部信号中断，不是代码问题。

### 第 1.5 层：Agent 链路自检（需 Agent 在线）

```bash
# 终端 A
python agent/agent.py ws://127.0.0.1:8765/ws/agent panel123

# 终端 B
python tests/agent_ping.py
# 期望：Agent 状态: 在线 / 链路正常：手机 -> 中枢 -> Agent 全通
```

这个脚本发的是一个无害的 `key_up`（释放未按下的键），屏幕上不会有任何反应，只验证链路。

## 第 2 层：PC 控制实测（手机 + 电脑）

### 准备
1. 中枢启动：`python -m uvicorn server.main:app --host 0.0.0.0 --port 8765`
2. Agent 启动：`python agent/agent.py ws://<电脑局域网IP>:8765/ws/agent panel123`
3. 查电脑 IP：`ipconfig`，记下 192.168.x.x
4. 手机连同一 WiFi，浏览器开 `http://<电脑IP>:8765`，输入令牌

### 验收清单（逐项打勾）

| # | 测试项 | 操作 | 期望 |
|---|--------|------|------|
| 1 | 状态灯 | 打开面板列表 | 绿点 = Agent 在线 |
| 2 | 触控板移动 | 单指滑动 | 光标跟手，无明显延迟（<100ms） |
| 3 | 左键 | 单指轻点 | 点一下，不连点、不误触 |
| 4 | 右键 | 双指轻点 | 弹出右键菜单 |
| 5 | 滚动 | 双指上下滑 | 方向自然（内容跟手） |
| 6 | 按住持续 | 长按 W 按钮 3 秒 | 游戏中持续前进，松开即停 |
| 7 | 组合键 | 按 Ctrl+C 按钮 | 复制生效 |
| 8 | 媒体键 | 按音量+/静音 | 系统音量变化 |
| 9 | **按键卡死保护** | 按住 W 时切到后台/锁屏 5 秒再回来 | 电脑上不会一直前进（中枢已下发 release_all） |
| 10 | Agent 掉线提示 | 杀掉 Agent 进程后按任意键 | 手机提示「PC Agent 未连接」 |
| 11 | 断线重连 | 重启 Agent | 5 秒内自动重连，状态灯变绿 |

### 布局编辑器验收

| # | 测试项 | 期望 |
|---|--------|------|
| 12 | 新建面板 | 模板弹层选 5 种模板；通用/手柄/媒体/电视进入使用模式，空白进编辑 |
| 13 | 拖动定位 | 拖动流畅，边缘不越界 |
| 14 | 改动作 | 改键名/模式/颜色后「使用」模式立即生效 |
| 15 | 保存持久化 | 保存后刷新页面，布局还在 |
| 16 | 删除元素 | 从布局和存储里都消失 |
| 17 | 多机共享 | 换一台手机打开，同一面板布局一致 |

## 第 3 层：电视实测（雷鸟鹤7 / ADB 协议）

### 电视端一次性设置
1. 设置 → 关于 → 连点「软件版本」7 次 → 提示进入开发者模式
2. 开发者选项 → 开启「网络调试 / USB 调试（网络）」
3. 记下电视 IP：设置 → 网络 → 当前网络详情

### 连接
1. 手机面板列表右上角「电视」→ 协议选 Android TV 系 → 填 IP → 保存
2. 点「连接测试」
3. 电视上会弹「允许 USB 调试吗」→ **勾选「一律允许」→ 确定**
4. 手机显示「已连接」

### 验收清单

| # | 测试项 | 期望 |
|---|--------|------|
| 1 | 方向键 | 电视焦点四向移动 |
| 2 | OK | 选中项进入 |
| 3 | 返回/桌面/菜单 | 对应层级跳转正确 |
| 4 | 音量±/静音 | 电视音量变化 |
| 5 | 电源 | 电视待机/唤醒（部分机型需长按，可用「唤醒」按键） |
| 6 | 启动应用 | 填包名能拉起对应 App |
| 7 | **PC 关机也能控** | 关掉 PC，电视按键仍有效（走 NAS） |
| 8 | 断电恢复 | 电视断电重开后，不用重新授权即可控（密钥已存） |

### 三星 / LG 协议
流程相同，端口 8001 / 3000，首次连接电视屏幕会弹「允许」。**这两个协议没有实机验证过**，若失败请保留「连接测试」返回的原始报错。

## 第 4 层：部署验收（NAS Docker）

```bash
docker compose up -d --build
docker compose logs -f          # 看启动是否有报错
curl "http://<NAS_IP>:8765/api/ping?token=<你的令牌>"
```

| # | 测试项 | 期望 |
|---|--------|------|
| 1 | 容器自启 | NAS 重启后自动恢复（restart: unless-stopped） |
| 2 | 布局持久化 | 重建容器后布局与电视配置仍在（卷挂载） |
| 3 | 手机经 NAS | 手机连中枢指向 NAS IP，PC 与电视都可用 |
| 4 | 权限 | 写令牌错误时手机提示「令牌错误」 |

## 排障速查

| 现象 | 排查顺序 |
|------|---------|
| 手机打不开页面 | 同一 WiFi？电脑防火墙放行 8765？`curl http://<IP>:8765` 通不通 |
| 页面能开但状态灯灰 | Agent 没启动 / 令牌不一致 / Agent 日志有 reconnect 报错 |
| 触控板移动很卡 | 手机 WiFi 信号弱；2.4G 频段拥塞 → 换 5G |
| 按键卡死（电脑一直输入） | 手机网页已断但 Agent 未收到释放 → 检查中枢日志；临时在电脑上按一下该键解除 |
| 电视连接失败 `failed to authenticate` | 电视上没点允许 / 未勾「一律允许」→ 删除 storage/adb_key 后重连 |
| 电视连接失败 `cannot connect` | 网络调试没开 / IP 变了 / 电视休眠断网 → 重开网络调试 |
| 电视按键无效但 adb 显示 device | 电视处于待机 → 先发「唤醒」；或前台是系统级界面不接收按键 |
| 安卓 11+ 电视端口不是 5555 | 无线调试端口随机 → 手机「电视设置」里改端口，或参考 adbctl 的端口扫描方案（待实现） |
| LG 连接超时 | 电视弹窗需在 20 秒内点「允许」；海外版可能要走 wss 3001（暂未支持） |

## 记录建议

实测时记下这四项，方便后续调优：**按键延迟（体感）、触控板灵敏度、按钮尺寸是否够按、电视按键响应延迟**。这些是手感参数，只能靠真实使用来定。
